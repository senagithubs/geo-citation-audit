# Next study: a small live visibility experiment

Status: proposed protocol, not executed. No live-engine observations are included
in the completed ALCE audit. Agree the engine, access method and query budget
with the client before starting.

1. Choose one business domain and 12 distinct English information needs. Freeze
   exact prompts and three matched formulations per need before collecting results.
2. Use one approved search-enabled engine surface, one locale and one account
   context. Record surface/model label, search setting, date, time and prompt.
3. Run each formulation three times in fresh sessions and randomise order within
   time blocks: 12 x 3 x 3 = 108 responses. Do not treat repeated responses as
   independent topics. If API access differs from the consumer UI, label it.
4. Preserve the full answer, cited URLs and retrieval timestamp. Distinguish a
   mentioned brand, a linked source and the actually supported claim. Keep
   evidence excerpts short and attributable; respect source access conditions.
5. Measure response-level citation incidence, domain presence across responses,
   citation stability and manually reviewed claim support. Freeze denominator
   rules for missing answers and inaccessible links; report failures separately.
6. Use a written review rubric and double-review a subset if another reviewer is
   available. Record disagreements. Mark unreviewed items as unreviewed.
7. Compare within the matched information need and report uncertainty clustered
   by that need. With 12 needs, frame this as a pilot, not a market-wide estimate.
8. Deliver raw observations, a data dictionary, script, charts, a short findings
   memo and limitations. A web-content intervention needs a separate design,
   permission to edit the site and a plan for indexation/time confounding.

German evaluation requires a verified German-speaking reviewer and a separate
translation/annotation quality process. It is not implied by the English study.
